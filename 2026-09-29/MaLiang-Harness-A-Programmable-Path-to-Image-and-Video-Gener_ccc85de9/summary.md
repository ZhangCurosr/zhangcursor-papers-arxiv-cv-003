# 论文速读：MaLiang-Harness-A-Programmable-Path-to-Image-and-Video-Gener

## 一句话总结
针对可执行视觉程序正确运行但无法满足视觉需求的 **Program-to-Visual (P2V) Gap**，本文提出 **MaLiang-Harness** 统一框架，通过持久化状态管理、可追溯操作记录与版本感知验证机制，使 MLLM 能够基于渲染反馈持续迭代修正；在自建的 **MaLiang-IBench** 与 **MaLiang-VBench** 上评测显示，**GPT-6-Astra** 达到 100% 生成成功率，且揭示了通用 MLLM 能力评分与可编程视觉生成性能之间存在显著预测脱节。

## 研究问题与动机
- **隐式生成缺乏可控性**：现有扩散/流匹配范式的生成过程高度隐式，难以提供显式的空间构图控制、可编辑性与创作过程可追溯性。
- **P2V Gap 的存在**：MLLM 生成的代码可能在语法与执行层面完全正确，但渲染结果仍会出现位置错误、时序错位或外观偏差，程序正确性≠视觉需求满足。
- **迭代修订缺乏状态支撑**：视觉创作需要多轮“生成-检查-修正”，但现有方法通常不保留中间状态与历史快照，导致模型难以进行精准回滚或基于证据的定位修复。
- **评测指标单一**：现有基准多关注生成成功率或端到端质量，缺乏对“执行链路可观测性”与“版本一致验证”的系统性衡量。

## 核心贡献（创新点）
- **形式化定义 P2V Gap 并构建状态化生成范式**：将视觉生成从单次代码生成重构为“构建-检查-修订”的持久化循环，与以往仅关注代码合成的工作形成本质区分。
- **提出 MaLiang-Harness 统一框架（PEG/TGP/REV）**：首次将持久化可执行状态、可追溯操作链路与版本绑定验证整合为跨渲染后端共享的协议，区别于 OmniHarness 等依赖单一搜索策略的方法。
- **设计版本感知的验证关闭条件**：通过数学形式化定义 `Ready(S_k)` 与审查证据绑定规则，确保每一次提交都必须基于当前版本的最新视觉证据重新验收，防止旧证据误判新代码。
- **建立 MaLiang-IBench/VBench 并揭示能力预测断层**：系统评测 11/4 个主流 MLLM，量化生成成功率、视觉质量与计算成本的trade-off，并证明通用 Benchmark 得分无法可靠预测可编程视觉生成表现。

## 方法详解
- **统一程序化视觉生成接口**：给定提示 $p$ 与输出规范 $\omega$，MLLM 规划外观、空间构图与时序动态，选择渲染后端 $b$（Canvas/SVG/Three.js 等）生成绘图与动画代码；当纯代码难以表达复杂外观时，允许引入图像资产作为补充。
- **PEG State（持久化可执行生成状态）**：定义 $S_k = (P_k, A_k, Z_k, C_k, k)$，其中 $P_k$ 为程序与后端标识，$A_k$ 为资产集合，$Z_k$ 嵌入时空构图属性，$C_k$ 保留任务上下文与当前计划（需求只增不减）。状态演进为 $S_{k+1} = \mathcal{E}(S_k, a_k)$，每次提交分配递增 $k$ 并保留历史快照。
- **TGP（可追溯生成过程）**：记录操作轨迹 $\tau_j = (o_j, x_j, y_j, k_j^-, k_j^+)$，将输入、执行结果/错误与源/目标版本关联。渲染观察 $I_k(t) = \mathcal{R}_b(S_k, t; \omega)$ 绑定到对应 $k$，支持将视觉偏差精确定位到具体代码修改，而非将“执行成功”等同于“视觉成功”。
- **REV（版本感知编辑与验证）**：维护每条视觉需求 $h_i$ 的审查记录 $q_i = (k_i, E_i, v_i)$，仅当 $k_i = k$ 时证据有效。完成条件为：
  $$\text{Ready}(S_k) = \text{ExportOK}(S_k) \wedge \text{CheckpointOK}(k) \wedge \bigwedge_{h_i \in \mathcal{H}_k} [k_i = k \wedge E_i \neq \emptyset \wedge v_i = \text{pass}]$$
  任何编辑提交后均触发重新验证；支持从历史 $S_r$ 恢复生成新版本 $S_{k+1}$ 并保留当前任务要求。

## 实验与结果
- **数据集与基线**：**MaLiang-IBench**（50 个文生图任务）评测 11 个 MLLM（DeepSeek/V4.1-Flash、V4-Pro、Kimi/K2.6、K2.7-Code、K3、GPT/5.6-Luna/Terra/Sol、6-Luna/Sol/Astra）；**MaLiang-VBench**（13 个文生视频任务）评测 4 个模型。质量由 GPT-6-Sol 作为 Judge，5 分制评估对齐度、美学、构图，视频额外评估运动连贯性。
- **核心数字**：**GPT-6-Astra** 在双基准均达 **100%** 生成成功率，**96.0%** 图像任务与 **76.9%** 视频任务满足全部质量阈值；对比 **GPT-5.6-Sol** 为 **86.0%**（图）与 **38.5%**（视频）。DeepSeek 与 Kimi 系列成功率仅 **12%–40%**，大量因 Token 预算耗尽失败。
- **效率权衡**：Astra 的 `Time/Qualified` 约为 3.70 min/image，GPT-5.6-Sol 为 3.28 min/image；视频 `Time/Success` 上 Astra 为 10.00 min/video，GPT-5.6-Sol 为 9.27 min/video。
- **关键发现**：AA Intelligence Index 与图像质量通过率仅呈中等正相关（Spearman $\rho = 0.65$）；相同分数模型（GPT-5.6-Luna 与 GPT-6-Luna 均为 37 分）质量通过率差异达 **44 pp**（44% vs 88%）；运动连贯性是视频生成最严格的瓶颈。
- **定性验证**：路径追踪后端可生成物理材质反射与接触阴影，但局部几何修改易引入伪影；纯笔触细化策略无法突破风格化表现向写实跳跃的瓶颈。

## 相关工作脉络
- **扩散/流匹配图像视频生成（Stable Diffusion, SVD）**：隐式像素合成，强调端到端质量；本文转向显式程序化表达，提供可编辑与可追溯优势。
- **VISPROG / Design2Code**：将视觉内容转为可执行代码，但侧重静态推理或单步渲染；本文引入多轮迭代与状态持久化闭环。
- **BlenderAlchemy / OmniHarness**：结合 VLM 与 3D/符号策略搜索编辑；本文提供跨异构渲染后端的统一协议，不依赖特定搜索算法。
- **Show-Harness / Code as Agent Harness**：通用代码代理基础设施；本文专门针对视觉生成的“状态-证据-版本”绑定需求进行定制。
- **ControlNet 等条件引导生成**：通过额外条件图干预扩散过程；本文通过代码直接声明几何/时序约束，支持更精确的结构级控制。

## 局限性与未来方向
- **写实生成能力受限**：Canvas/矢量后端难以独立实现摄影级真实感，路径追踪等重型后端引入成本高且局部修订易产生伪影。
