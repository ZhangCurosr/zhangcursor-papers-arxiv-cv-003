# 论文速读：HPMD: A Historical Persian Manuscript Dataset for Word Spotting with Line-Level Annotation

## 一句话总结
本文构建了首个面向历史波斯手写稿的词级检索数据集 HPMD（223 页、3,678 行、37,631 词），并提出一种仅需行级标注的 word spotting 基线：将 CTC 识别器输出的逐帧后验概率矩阵直接用于查询评分，避免了解码过程中的字符混淆，并在测试集上实现了 F1 = 0.558 的词检索性能。

## 研究问题与动机
1. **历史波斯手稿缺乏可检索性**：大量手稿已完成数字化扫描，但历史学家查找特定人名、日期或事件仍需逐页人工翻阅，亟需自动化工具将搜索从"数月"缩短至"数分钟"。
2. **现有数据集无法覆盖历史材料**：已公开的波斯手写数据集（Sadri、Khayyam、Hoda、FHT、MPHD）均为现代书写者填写于标准表格上的文本，缺少历史手稿特有的版式、装饰纹样、书体风格与老化退化；OpenITI MAKHZAN 虽有历史材料，但其波斯语部分占比很小。
3. **词级边界框标注成本过高**：主流 word spotting 方法依赖词级 bounding box 标注，对 200 页手稿约需 2,000 个行区域框和约 20,000 个词级框，在低资源语言/历史材料场景下，标注成本是数据集稀缺的主因。
4. **标准 OCR 检索方案失效**：波斯文字母同形异点（如 be/pe/te/se、jim/che/he/khe），古手稿中点迹常模糊、错位或缺失；标准识别器逐帧取 argmax 输出单一字符串，一个字符出错即导致整词匹配失败。

## 核心贡献（创新点）
1. **发布 HPMD 历史波斯手写数据集**：包含 223 页诗歌与散文混合的历史手稿，由 11 位标注员完成区/行/文本三级标注，并附带页面级属性标签（体裁、书体、退化程度、装饰、阅读难度）与分布分析——这是首个针对历史波斯手写材料的公开数据集，区别于现有仅含现代手写体的波斯数据集。
2. **提出 CTC 后验矩阵直接检索方法**：不依赖词级标注，仅用行级转录训练 CTC-CRNN 识别器，保留完整逐帧后验概率矩阵 $Y \in [0,1]^{T \times (K+1)}$，将查询直接与矩阵对齐评分——与传统"解码→文本搜索"范式本质不同，后者因 argmax 硬决策而丧失对近形字符混淆的容忍度。
3. **建立完整可复现基线与详尽评估协议**：包括微调后的 BLLA 行检测器、CRNN 识别器、显式阈值选择协议（在验证集上最大化 F1）、与 PHOC 属性嵌入基线（以 oracle 词边界为理论上限）的对比、错误分类学以及按页面属性的性能分解——为后续研究者提供了统一的比较基准。

## 方法详解
- **Pipeline 总览**：三阶段流水线——行检测 → 行级识别 → 后验矩阵检索（图 5）。全部模型基于 kraken 引擎训练。
- **行检测（Line Detection）**：微调 Kiessling [10] 提出的 BLLA（Baseline and Layout Analysis）模型，预测页面级 baseline 和 region 热图，再转换为行多边形；每行被裁剪并校正为直线图像送识别器。
- **识别器（Recognition）**：微调 kraken 预训练的 `all_arabic` 模型（CRNN + CTC 损失），输入图像宽度自由、高度固定；双向 LSTM 读取从左到右的帧序列，输出每帧 $K+1$ 类字符 softmax 分布（含 CTC blank）。波斯语从右向左书写，kraken 使用 Unicode 双向算法将标签按显示顺序排列，查询亦做相同重排。
- **后验矩阵（Posterior Matrix，公式 1）**：对 $T$ 帧行图像，识别器输出 $y_t(c)$ 为帧 $t$ 上字符 $c$ 的概率，满足 $\sum_c y_t(c) = 1$。
- **查询评分（Scoring，公式 2–6）**：将归一化查询 $q = (q_1, \ldots, q_L)$ 扩展为含 blank 的序列 $q'$（长度 $2L+1$），用 Viterbi 递归寻找最优对齐路径，得分经帧级归一化 $r_t(c) = \log y_t(c) - \max_k \log y_t(k) \leq 0$ 后累加，最终得每字符对数得分 $s(q) = S(q)/L \leq 0$，等价置信度 $C(q) = \exp(s(q)) \in (0, 1]$；当 $s(q) \geq \tau$ 时判定该行包含查询词。
- **词位置恢复（公式 7）**：最优对齐路径给出首帧 $t_s$ 与末帧 $t_e$，在宽 $W$ 的行图像中估算词的水平边界 $x_{\text{start}} = \frac{t_s}{T}W$、$x_{\text{end}} = \frac{t_e+1}{T}W$，垂直范围取自检测到的行多边形，映射回页面坐标即得词级位置——全程无需词级标注。
- **Exact-Match 基线**：对同一识别器输出取 argmax 解码，再在解码文本中做精确词匹配，位置同样由帧对齐恢复。
- **PHOC 属性嵌入基线**：42 符号字母表、5 层金字塔直方图编码为 630 维二进制向量；卷积网络 + binary cross-entropy 训练；查询侧解析生成 PHOC 后余弦相似度检索。该基线使用 GT 转录强制对齐得到的 oracle 词边界，作为强监督方法的理论上限。

## 实验与结果
- **数据集与划分**：223 页，行级划分：训练 144 页（2,329 行/24,301 词）、验证 35 页（614 行/6,079 词）、测试 44 页（735 行/7,251 词）。396 个独立查询词（每页随机选 ≥3 字符词 10 个）。
- **超参**：学习率 $10^{-4}$，batch size 8，40 epochs。
- **行检测结果（表 VII）**：微调后 F1 = 0.892（Precision 0.867 / Recall 0.920），较基础模型 F1 0.793 提升显著；mean IoU 0.534。
- **词检索主结果（表 IX）**：后验检索将 F1 从 exact OCR 的 0.487 提升至 **0.558**，Recall 从 0.340 提升至 **0.548**（$\tau^* = -0.80$ 由验证集最大化 F1 选取，对应置信度 0.45）。
- **vs PHOC 基线（表 X）**：PHOC（oracle 词边界）行级 F1 = 0.449、mAP = 0.266；后验检索行级 F1 = 0.558、mAP = 0.564，在更强监督条件下仍胜出。
- **阈值敏感性（表 VIII）**：F1 曲线在 $\tau^*$ 附近 ±0.3 范围内平缓；Recall ≥ 0.90 需 $\tau = -2.42$，此时 Precision 仅 0.071。
- **按查询长度分解（表 XI）**：≥7 字符查询 Precision = 1.000，F1 = 0.615；3–4 字符查询 F1 = 0.543，短词是主要误差来源。
- **按页面属性分解（表 XIII）**：无装饰页 F1 = 0.652，仅边框 F1 = 0.481，边框+鎏金云背景 F1 = 0.383，**装饰背景造成 0.269 F1 损失**，为最强条件因子。

## 相关工作脉络
1. **历史阿拉伯文数据集 VML-HD [6]**：专为词检索设计，但面向阿拉伯文，不含波斯语；本文填补波斯语历史手写数据集的空白。
2. **OpenITI MAKHZAN [8]**：涵盖阿拉伯文/波斯文/奥斯曼土耳其文/乌尔都语的多语种手稿，但波斯语部分有限且主要用于转录训练；本文补充了大量波斯语历史诗歌与散文材料，并引入行级轻量标注方案。
3. **PHOCNet [14] / Ctrl-F-Net [15] / HWNet v3 [17]**：均依赖词级 bounding box 标注或强监督；本文方法仅需行级标注，利用 CTC 帧对齐自然恢复词位置，训练成本大幅降低。
4. **HATFormer [11] / TrOCR [18]**：基于 Transformer 的历史手写识别模型，输出为文本字符串，与本文后验矩阵检索思路不同；本文方法可作为上述识别器的即插即用检索模块。
5. **现代波斯数据集（Sadri [1] / Khayyam [2] / MPHD [9] 等）**：均由现代书写者填写标准表单，缺少历史手稿的版式、装饰与退化特征；本文数据集在书体（shekasteh 占主导）、装饰、退化等维度上与现代数据集有本质差异。
6. **Kraken BLLA 行检测 [10]**：本文以其为行检测起点并微调适配历史波斯材料，延续了 kraken 框架对曲线/旋转行的良好处理能力。

## 局限性与未来方向
1. **词级定位精度无法量化**：数据集无词级边界框，水平位置仅由帧对齐估算，无法提供精确的 bounding box 评估；图 7 中的红框仅为示意。
2. **子串匹配是主要精度损失来源**：错误分析显示 53.4% 的假阳性为查询词作为长词的子串被命中，而非字符混淆（仅 1.6%）；方法解决了设计动机，但剩余精度问题需另寻低成本修复（如要求匹配首尾为 blank 帧）。
3. **测试集偏小**：44 页测试集中少数属性类别样本极少（如 naskh 仅 2 页、中度退化仅 3 页），按条件分组的结论可靠性不足。
4. **主观难度标签混淆严重**："hard"类别与 shekasteh 书体几乎完全重叠，"degradation"类别与书体和装饰高度共线，难以作为独立条件变量使用；未来需用自动计算的客观指标（模糊度、对比度、基线曲率等）替代。
5. **装饰背景（鎏金云纹）影响显著**：背景去除（background suppression）而非序列建模改进，是下一阶段性能提升的关键方向。

## 研究启发与可借鉴点
1. **后验矩阵检索替代解码搜索**：将 CTC 逐帧后验矩阵用于直接查询对齐评分，而非先 argmax 解码再匹配，可显著提升对近形字符混淆的容忍度；该策略可迁移至其他同形异点文字系统（如阿拉伯文、乌尔都文）。
2. **行级轻量标注 + 帧对齐恢复词位置**：用低成本行级标注训练识别器，通过 CTC 帧对齐自然获得词级位置，避免了昂贵词级框标注；对低资源语言/历史材料的数据集构建具有重要参考价值。
3. **错误分类学的量化价值**：本文不仅报告 aggregate F1，还按查询长度、点符比例、页面属性分解性能，并给出假阳性分类学（子串/无关/同骨架不同点），为后续研究提供了精准的改进方向定位。
4. **oracle 强基线对照设计**：PHOC 基线使用 GT 强制对齐的 oracle 词边界，明确作为强监督方法的 upper bound；这种"放宽条件"的对照方式有助于客观评估所提方法的实际性价比。
5. **页面级属性标签的附加价值**：在数据集中预置体裁、书体、退化、装饰等多维属性标签，支持细粒度性能分析，便于后续研究隔离不同因素对模型的影响。

## 关键术语表
- **Word Spotting**：无需完整转录，直接从文档图像中检索与查询词匹配的图像区域，同时返回其位置信息。
- **CTC（Connectionist Temporal Classification）**：用于序列标注的损失函数，允许输入帧与输出符号之间进行非线性对齐，只需序列级标签，无需帧级对齐标注。
- **Posterior Matrix**：识别器输出的逐帧字符概率矩阵 $Y \in [0,1]^{T \times (K+1)}$，保留模型在每个时间步对所有字符的不确定性分布。
- **PHOC（Pyramidal Histogram of Characters）**：将单词图像编码为固定长度的二进制直方图，记录各相对位置出现的字符集合，使图像与字符串可映射到同一空间进行检索。
- **BLLA（Baseline and Layout Analysis）**：Kiessling 提出的模块化行检测网络，预测 baseline 和 region 热图并将 baselines 转换为行多边形。
- **Shekasteh（ شکسته）**：波斯手写书法体之一，字母高度连写、点迹常省略，是本文数据集的主导书体（173/223 页）。
- **Transkribus**：开源的手稿转录平台，支持多人协作标注，本文用于行级文本标注。
- **CTC Forced Alignment**：利用已知的 GT 转录与后验矩阵进行动态规划对齐，得到每个字符/词的帧跨度，用于提取词级裁剪区域。

## 可复现要素
- **数据集**：HPMD，223 页历史波斯手写稿；开源链接：https://github.com/saeed5959/persian_handwritten_dataset；许可证 CC BY-NC 4.0。
- **代码**：论文声明开源（同上 GitHub 仓库），基于 kraken 引擎。
- **关键超参**：学习率 $10^{-4}$，batch size 8，40 epochs；行检测 IoU 阈值 0.3；后验检索阈值 $\tau^* = -0.80$（对应每字符置信度 0.45，在验证集上最大化 F1 选取）。
- **训练配置**：BLLA 与 `all_arabic` CRNN 均从 kraken 预训练权重微调；文本预处理包括去重音、alef 归一化、Arab yeh/kaf 转 Pers 对应形、零宽不连字符替换为空格、去除标点。
- **数据划分**：页面级划分，训练 144 页 / 验证 35 页 / 测试 44 页，无页面跨集泄漏。
