# 论文速读：HPMD-A-Historical-Persian-Manuscript-Dataset-for-Word-Spotti

## 一句话总结
本文提出了HPMD数据集（223页历史波斯手写稿，3678行，37631词，130630字符），并设计了仅用行级标注即可实现词级定位的后验矩阵搜索方法，将词定位F1从0.487提升至0.558，有效解决了历史波斯手稿检索中的标注成本与字符混淆问题。

## 研究问题与动机
1. **数据稀缺**：现有波斯手写数据集（Sadri、Khayyam、FHT、MPHD等）均为现代人在标准表格上书写，缺乏历史手稿的真实布局、装饰、退化特征；OpenITI MAKHZAN虽有手稿但波斯语部分有限。
2. **标注成本高**：传统词定位方法依赖词级边界框标注，约需20000个词框（200页规模），对低资源语言是主要瓶颈。
3. **字符混淆导致检索失败**：波斯语中be/pe/te/se、jim/che/he/khe等字母仅靠点数区分，历史手稿中圆点易模糊或缺失，标准OCR的单字符argmax解码会将正确词直接丢弃。
4. **历史研究者需求**：历史学家需要定位特定人名、日期、事件的出现位置，而非完整转录全文。

## 核心贡献（创新点）
1. **新数据集HPMD**：涵盖诗歌与散文、三种书体（shekasteh/nastaliq/naskh）、多种装饰与退化程度，附带页面级属性标注与分布分析——区别于现有现代手写数据集，填补历史波斯手稿空白。
2. **后验矩阵搜索方法**：保留CTC识别器的逐帧后验概率矩阵，将查询直接与矩阵对齐打分，而非解码为文本后搜索——使搜索对相似字符混淆具有容忍性。
3. **行级标注驱动词级定位**：模型仅需行级转录训练，通过CTC帧对齐恢复词在行内的水平位置——避免了昂贵的词级边界框标注。
4. **完整可复现基线**：包括调优后的BLLA行检测器（F1=0.892）、CRNN识别器、阈值选择协议、PHOC属性嵌入对比基线（含oracle词边界上界）及错误分类分析。

## 方法详解
**三阶段流水线**：
1. **行检测**：Fine-tune Kiessling的BLLA模型（预测基线与区域热图，转为行多边形），IoU≥0.3判定匹配，测试集F1=0.892。
2. **识别**：Fine-tune all_arabic CRNN（Conv+BiLSTM+CTC），输入行图像固定高度、自由宽度，输出T帧×(K+1)维后验矩阵Y。
3. **后验搜索**：
   - 查询q'=(∅,q₁,∅,...,∅,q_L,∅)长度为2L+1
   - 帧归一化得分：r_t(c)=log y_t(c)−max_k log y_t(k)≤0
   - Viterbi对齐：δ_t(s)=r_t(q'_s)+max{δ_{t−1}(s), δ_{t−1}(s−1), δ_{t−1}(s−2)}
   - 最终分：S(q)=max_t max{δ_t(2L), δ_t(2L+1)}，每字符归一化s(q)=S(q)/L≤0
   - 阈值τ从验证集选（τ*=−0.80，对应置信度0.45），多匹配返回不重叠结果
4. **位置恢复**：最优路径首尾帧t_s、t_e映射为x_start=(t_s/T)·W，x_end=((t_e+1)/T)·W，垂直范围取自行多边形。

## 实验与结果
**数据集**：HPMD，223页/3678行/37631词/130630字符；Train 144页、Val 35页、Test 44页（页级划分）。
**评估协议**：随机抽取396个≥3字符查询词，每个在测试集所有行中搜索，约2.8×10⁵查询-行对，1430个正样本。
**核心结果**：
- 行检测：Fine-tune后F1=0.892（Precision=0.867, Recall=0.920, Mean IoU=0.534）
- 词定位：后验搜索F1=0.558（Precision=0.570, Recall=0.548），相对精确匹配（F1=0.487）提升14.6%
- Recall从0.340→0.548，Precision从0.857→0.570
- PHOC基线（oracle词边界）F1=0.449，低于后验方法
**阈值敏感性**：F1曲线在τ*±0.3范围内平坦；高精度区（P≥0.90）需τ=−0.02，但Recall仅0.009；高召回区（R≥0.90）需τ=−2.42，Precision仅0.071。
**按查询长度**：3-4字符F1=0.543，5-6字符F1=0.651，7+字符F1=0.615（Precision达1.000）。
**按页面属性**：无装饰F1=0.652，仅边框F1=0.481，边框+金箔云背景F1=0.383（下降0.269）；难度/退化标签因分布混杂不可靠。
**错误分析**：635个假阳性中53.4%为子串匹配，45.0%为无关词，仅1.6%为同骨架不同圆点——说明方法解决了设计目标（圆点混淆），但子串歧义是主要误差来源。

## 相关工作脉络
1. **VML-HD（阿拉伯语历史数据集）**：专为词定位设计，但语言不同；本文针对波斯语历史手稿，覆盖更多书体与装饰类型。
2. **PHOCNet/Ctrl-F-Net/HWNet v3**：词定位经典方法依赖词级边界框；本文用行级标注+后验搜索实现同等目标，避免昂贵标注。
3. **Sadri/Khayyam/FHT/MPHD**：现代波斯手写数据集，用于识别训练；本文强调历史手稿的真实退化、装饰、布局复杂性。
4. **OpenITI MAKHZAN**：多语言阿拉伯脚本手稿，波斯语部分有限且主要为转录设计；本文提供专用波斯语历史词定位数据集与任务导向基线。
5. **HATFormer/TrOCR**：Transformer架构用于历史手稿识别；本文采用CRNN+CTC，强调后验矩阵利用而非纯识别精度。
6. **PuReCNN**（未直接引用但相关）：基于后验矩阵的词定位方法；本文在后验搜索思路上独立发展，并系统评估了与PHOC方法的对比。

## 局限性与未来方向
1. **词级位置估计不精确**：帧对齐提供近似水平边界，无词级标注无法量化定位精度；图7红框仅为示意。
2. **子串匹配导致假阳性**：53.4%假阳性来自查询作为更长词子串匹配；需强制两端空白帧或引入词典/语言模型约束。
3. **小样本导致条件分析不可靠**：naskh（2页）、中度退化（3页）等少数类别结果不稳定；需更平衡测试集或自动计算质量分数。
4. **主观难度标签失效**：difficulty标签与书体高度混杂，建议未来替换为基于模糊度/对比度/基线曲率的自动度量。
5. **测试集规模有限**：44页测试集难以覆盖所有历史手稿变异，跨书籍泛化需进一步验证。

## 研究启发与可借鉴点
1. **后验矩阵保留策略**：CTC识别器放弃argmax解码而保留完整后验矩阵，可推广至其他易混淆字符脚本（如阿拉伯语、乌尔都语），以检索精度替代转录精度。
2. **行级标注降成本**：用CTC帧对齐恢复词位置，避免词级边界框标注；适用于低资源语言/历史文档，大幅降低标注成本。
3. **误差归因分析框架**：将假阳性分为子串匹配/无关词/字符混淆三类，揭示方法设计目标与实际误差分布的差异，指导后续改进方向。
4. **阈值鲁棒性验证**：在验证集选阈值并冻结，测试时不调优，且报告阈值敏感性曲线——为部署场景提供可复现的阈值选择协议。
5. **页面属性条件化评估**：按装饰、退化、书体分组报告性能，帮助未来工作识别真正瓶颈（本文明确 illumination 是最强因素）。

## 关键术语表
**HPMD**：Historical Persian Manuscript Dataset，本文提出的223页历史波斯手写稿词定位数据集。
**Word Spotting**：词定位，无需完整转录即可在文档图像中检索并定位查询词出现位置的任务。
**CTC（Connectionist Temporal Classification）**：连接时序分类，用于序列识别的训练损失函数，允许输入输出长度不同，输出逐帧字符后验概率。
**Posterior Matrix**：后验矩阵，识别器输出的T×(K+1)维概率矩阵，记录每帧每个字符（含空白符）的概率。
**BLLA（Baseline and Layout Analysis）**：Kiessling提出的行检测模型，预测基线与区域热图并转为行多边形。
**PHOC（Pyramidal Histogram of Characters）**：金字塔直方图字符编码，将词图像编码为固定长度二进制向量，支持字符串与图像的同一空间检索。
**Shekasteh/Nastaliq/Naskh**：三种波斯书法书体；shekasteh为最潦草连笔体，难读但历史文献最常见；nastaliq为装饰性书体；naskh为标准印刷体。
**Tazhib**：波斯手稿装饰技法，包括边框（border）和云状金箔背景（gilded cloud background），后者显著降低文字对比度。
