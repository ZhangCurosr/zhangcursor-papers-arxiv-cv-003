# 论文速读：ROBOQUEST-GENERALIST-PHYSICAL-AGENTS-THAT-SEARCH-INSPECT-AND-TEST

## 一句话总结
本文提出 **RoboQuest**，一个面向目标导向具身探索的基准测试，包含10个移动操作任务（搜索、检查、测试三类），要求智能体主动通过物理交互获取任务关键信息后再决策。评估发现，最优前沿多模态代理（GPT-6 Astra）成功率仅 **23.2%**，失败主因是探索不足与过早决策，而非执行技能缺陷。

## 研究问题与动机
1. **现有基准的信息完备性假设脱离现实**：主流操作基准（RLBench、CALVIN、LIBERO等）假设任务关键信息在初始观测中完全可见，智能体只需执行正确动作即可成功，缺乏对“主动获取信息”能力的评估。
2. **前沿多模态代理的执行能力已较强，但探索决策能力未知**：GPT‑6、Claude Opus等模型已能直接控制机器人完成复杂操作，但在信息缺失的环境中，它们如何决定“去哪里找”“检查什么”“何时足够”尚不清楚。
3. **缺乏架构中性、可严格评分的具身探索基准**：当前主动感知基准多局限于视角调整或单步解遮挡，未涵盖搜索、主动检查、交互测试三种核心探索形式，也无法隔离执行与决策失败。

## 核心贡献（创新点）
1. **提出RoboQuest基准**：包含10个精心设计的移动操作任务，按信息获取方式分为Search（3）、Inspect（3）、Test（4）三族，任务目标仅给出外部可验证的物理状态，探究策略完全交由智能体自主决定。
2. **发布5000集示范数据集（500集/任务）**：由脚本化Oracle生成，探索过程模拟无先验知识的智能体，每帧含两级语言标注（阶段+子任务），总交互时长366小时（20 Hz），训练集与测试集在厨房布局、风格、任务配置上完全持留。
3. **系统评估五类前沿多模态代理与一个微调π₀.₅策略**：统一视动接口下，GPT‑6 Astra以23.2%整体成功率领先，但即使最强代理仍在搜索与检查任务上几乎零成功；微调π₀.₅在保持出分布场景下成功率趋近于0。
4. **提出细粒度失败归因框架**：将每次失败单元归入四大类——**缺失证据**（未探索到关键信息）、**错误决策**（已获得证据但未正确使用）、**副作用**（探索动作破坏场景且未修复）、**执行失败**（动作物理执行失误），揭示探索与决策才是性能瓶颈（占66‑74%失败）。

## 方法详解
### 基准设置
- **环境**：基于RoboCasa365厨房，在MuJoCo物理引擎中模拟，Franka Panda机械臂搭载移动底盘，控制频率20 Hz，三摄像头（左/右场景+腕部）观测。
- **任务结构**：10个任务，每个任务提供自然语言目标描述，关键隐藏信息（如物体位置、标记、开启机制）置于Agent不可见的私有规范中。
- **Episode终止**：智能体必须物理按压场景中的**SUBMIT**按钮才能结束回合，按压瞬间冻结状态并评分；超时200次决策或未提交均判为失败。
- **实例生成**：每任务50个实例，覆盖18种厨房布局、5种风格，部分任务含三级遮挡（Visible/Look/Uncover）。

### 三类不确定性任务
| 家族 | 任务 | 隐藏信息 | 揭示方式 |
|------|------|----------|----------|
| Search | Locked Storage | 目标在锁后 | 找到颜色令牌解锁各隔间 |
| Search | Search Room | 目标位置未知 | 搜索各开放/封闭存放点 |
| Search | Blackout Search | 黑暗中的目标 | 携带光源逐区域照明搜索 |
| Inspect | Painted Cubes | 不可见面上的标记 | 翻转立方体查看各面 |
| Inspect | Marked Mugs | 容器底部标签 | 提起/倾斜容器读出标签 |
| Inspect | Unfamiliar Containers | 容器开启机制 | 尝试不同旋钮动作 |
| Test | Puzzle Box | 螺栓解锁顺序 | 尝试滑动并观察联动 |
| Test | Stamp Composition | 印章图案与旋转 | 在试印板打印试验 |
| Test | Wobbly Stand | 短腿位置与间隙 | 放置小球观察滚动方向 |
| Test | Odd Parcel | 哪个包裹异常 | 用天平分组称重比较 |

### 评估协议
- **前沿代理**：GPT‑6 Astra、Claude Opus 5.5、GPT‑6.1 Sol、Claude Fable 5.1、Gemini 3.8 Flash，统一通过Inspects Robots框架接入，每决策接收三张512×512图像+本体觉+剩余预算，输出ARM/BASE/WAIT/STOP四工具调用。
- **执行技能隔离测试**：对Top 3代理，在隐藏信息已知前提下单独测试各项物理技能（抓取、驱动、开抽屉、翻转立方体等），成功率72‑81%，显著高于完整任务表现，证明执行非瓶颈。
- **微调策略**：在5000集演示数据上SFT π₀.₅（VLA），训练损失为流匹配动作损失+因果子任务预测交叉熵（权重比10:1），全参数微调，AdamW，cosine LR 2.5e‑5，batch 32；推理时以1 Hz闭环重规划。

### 能力分解与失败归因
将完成任务所需能力分为四类：**证据获取**（发现并揭示隐藏信息）、**证据使用**（整合记忆观测）、**交互推理**（从互动结果推断隐藏结构）、**行动组织**（规划序列与预判后果）。每次失败按首个不可恢复错误归入：
- **Missing evidence**（43‑46%）：关键信息从未被探索到（如抽屉未打开、立方体未翻转）。
- **Wrong decision**（23‑31%）：证据已观测但未正确使用（如误读标签、过早提交）。
- **Side effect**（7‑13%）：探索动作引发不可逆破坏且未修复（如打翻杯子、小球滚落）。
- **Execution failure**（18‑21%）：物理动作执行失误（抓握失败、放置偏移）。

## 实验与结果
### 主要结果（Table 3）
| 模型 | 整体SR | 整体Prog | 去除Puzzle Box后SR |
|------|--------|----------|---------------------|
| GPT‑6 Astra | **23.2%** | 48.0% | **15.1%** |
| Claude Opus 5.5 | 13.8% | 37.3% | 7.8% |
| GPT‑6.1 Sol | 12.2% | 34.0% | 5.6% |
| Claude Fable 5.1 | 11.4% | 31.0% | 4.9% |
| Gemini 3.8 Flash | 2.0% | 9.2% | 0.9% |

- ** hardest tasks**：Blackout Search全模型0成功，Search Room仅Gemini 3.8 Flash成功1次；** easiest task**：Puzzle Box GPT‑6 Astra达96%，其余模型68‑72%，故额外报告去除该任务后的均值。
- **成本分析**（Table 7）：5模型500集共花费$21,352；GPT‑6.1 Sol每成功 episode 成本最低（$16.3），Fable 5.1与Gemini 3.8 Flash每成功成本最高（$168+）。

### 执行技能隔离测试（Table 4）
- 通用技能（驱动+抓取、放置）成功率90‑100%。
- 任务特定技能：翻转立方体100%，开指定容器90‑100%，但开抽屉/柜子仅30‑60%，从抽屉取物60‑70%，垫 shim 35‑60%。
- **反直觉发现**：在完整任务中开抽屉成功率（75‑90%）显著高于隔离测试（30‑60%），且决策次数更少（平均10步 vs 22‑36步），推测连续任务中模型更快适应控制。

### 微调π₀.₅表现（Fig. 4）
- 整体成功率接近0，除Puzzle Box（2%）外所有任务0成功，多数因超时退出；证明标准VLA在目标导向探索任务上泛化能力极弱，无法通过记忆状态‑动作映射解决OOD场景。

### 失败归因（Fig. 5, Table 16）
- **Missing evidence** 占主导：GPT‑6 Astra 43%、Opus 5.5 43%、GPT‑6.1 Sol 46%。
- **Wrong decision** 次之：23‑31%，其中约10‑11%为“过早决策”（未观测足够证据即提交）。
- **Side effect** 7‑13%，主要由探索动作引发场景破坏且未修复（如Marked Mugs中倒出小球后未回收）。
- **Execution failure** 仅18‑21%，印证执行非瓶颈。
- 遮挡实验（Table 14）：引入Look/Uncover遮挡使成功率下降8‑10点，新增失败全归因于Missing evidence，进一步证实探索不足是核心瓶颈。

## 相关工作脉络
1. **传统操作基准**（RLBench、CALVIN、LIBERO、ManiSkill3、RoboTwin 2.0、BEHAVIOR‑1K、RoboCasa365）均以执行技能为核心，假设信息完全可见，缺乏对证据寻求能力的设计与评估。
2. **主动感知基准**（Liu et al., 2026b/a; He et al., 2026; Li et al., 2026a）多局限于相机视角调整或单步解遮挡，未涵盖搜索、主动检查、交互测试三种物理探索形式，也未评估探索对环境的不可逆影响。
3. **具身推理与VLA评估**（Liang et al., 2023; Brohan et al., 2023; Physical Intelligence et al., 2025）均在fully observed场景中测试，未考察信息缺失下的决策瓶颈；本文首次在同一基准上公平比较zero‑shot规划型代理与learned VLA策略。
4. **交互式感知理论**（Bajcsy, 1988; Bohg et al., 2017）强调通过主动动作获取信息，但缺乏可量化的机器人执行基准；RoboQuest将这一理论转化为可自动评分、细粒度归因的实证平台。
5. **RMBench**（Chen et al., 2026a）关注记忆依赖操作，但未要求主动探索；本文与之互补，聚焦于“主动获取证据”而非“保持历史状态”。

## 局限性与未来方向
1. **模拟环境局限**：所有任务在MuJoCo中运行，物理材质、视觉纹理虽多样，但缺乏真实机器人噪声、传感器漂移、执行器故障等现实挑战。
2. **内存与上下文管理**：当前接口仅保留最近两帧图像，长期探索任务（如Blackout Search需记住已搜索区域）可能受限于上下文窗口。
3. **任务复杂度有限**：10个任务均为单臂移动操作，未涉及双臂协同、动态障碍物、多智能体交互等更复杂场景。
4. **探索策略单一**：Oracle示范数据由确定性脚本生成，未能覆盖人类或高级代理的多样化探索习惯，可能限制训练数据的丰富性。
5. **未来方向**：① 引入真实机器人闭环测试；② 设计显式记忆机制（如向量数据库、世界模型）以跟踪证据积累；③ 扩展至更多样化的物理交互（如流体、柔性物体）；④ 研究从失败回放中自我改进的元学习算法。

## 研究启发与可借鉴点
1. **失败归因框架可迁移**：Missing/Wrong/Side‑effect/Execution四分类法可复用至其他探索基准，帮助快速定位性能瓶颈，指导后续算法设计。
2. **隔离测试验证假设**：通过“隐藏信息已知”的隔离技能测试，有效分离执行与决策失败，为后续研究提供清晰的评估分解方式。
3. **遮挡与工作量参数化**：三级遮挡（Visible/Look/Uncover）与低中高工作量（三水平）设计便于控制难度梯度，可借鉴用于其他基准的难度调节。
4. **演示数据生成策略**：Oracle虽知晓答案，但强制其模拟无先验知识的探索过程（如最近优先、试错固定顺序），保证了示范数据的“教学价值”，而非简单最优轨迹。
5. **成本‑性能联合评估**：同时报告成功率、进度、每成功episode成本、token消耗、墙钟时间，为实际部署提供全面权衡视角，可推广至其他AGI‑robotics评估。

## 关键术语表
- **RoboQuest**：目标导向具身探索基准，要求智能体通过物理交互主动获取缺失信息后再决策完成物理任务。
- **Evidence‑seeking manipulation**：以证据收集为核心的操作范式，区别于传统“执行已给定信息”的操作。
- **Active perception**：通过主动动作（而非被动观看）获取任务相关信息，如翻转物体、尝试开启机制。
- **Interactive testing**：通过系列试验（如称重、印测试）从环境反馈中推断隐藏属性（如重量差异、图案）。
- **VLA（Vision‑Language‑Action）**：端到端视觉‑语言‑动作模型，直接将图像和指令映射为低层控制命令。
- **Missing evidence**：失败归因类别，指关键信息从未进入Agent观测，多因探索不彻底导致。
- **Side effect**：失败归因类别，指探索动作成功执行但破坏了场景状态且未修复（如打翻容器）。
- **SUBMIT press**：任务终止信号，物理按压按钮瞬间冻结状态评分，强调智能体需自主判断证据是否充分。

## 可复现要素
- **数据集**：RoboQuest Demonstration Dataset（5000集，LeRobot v2.1格式）已公开，项目主页 https://declare‑lab.github.io/RoboQuest/。
- **代码与基准**：评估harness基于Inspects Robots框架（GitHub: robocurve/inspect‑robots），任务脚本与评测代码随论文发布。
- **训练超参**：π₀.₅微调采用AdamW（β₁=0.9, β₂=0.999, ε=1e‑8），weight decay 1e‑4，peak LR 2.5e‑5，cosine schedule with 1000 warmup steps，global batch size 32，gradient clipping norm 1.0，flow loss multiplier 10.0，action normalization quantile (q01, q99)。
- **环境**：MuJoCo 2.3.3，RoboCasa365厨房asset，Franka Panda arm on mobile base，20 Hz控制频率，三摄像头512×512 RGB。
- **接口约束**：每决策输出ARM/BASE/WAIT/STOP四工具之一，最长10秒模拟时间，单episode最多200次决策。
